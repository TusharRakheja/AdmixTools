# ADMIXTOOLS — Windows build

[![regression](https://github.com/TusharRakheja/AdmixTools/actions/workflows/regression.yml/badge.svg?branch=v8.1.0-win-1)](https://github.com/TusharRakheja/AdmixTools/actions/workflows/regression.yml)
[![latest release](https://img.shields.io/github/v/release/TusharRakheja/AdmixTools?label=release)](https://github.com/TusharRakheja/AdmixTools/releases/latest)

A fork of [DReichLab/AdmixTools](https://github.com/DReichLab/AdmixTools) that
builds and runs on Windows, published as ready-to-use binaries.

**Upstream documentation is unchanged and still authoritative** — see
[`README`](README) for what the programs do and how to use them, plus the
`README.*` files for individual tools. This page only covers the Windows build.

## Download

Grab the zip from [Releases](https://github.com/TusharRakheja/AdmixTools/releases),
unpack it anywhere, and add the `bin` subfolder to `PATH`. Cygwin does **not**
need to be installed; every required runtime library is bundled.

```
qpDstat          # should print usage
```

Read `README-WINDOWS.txt` inside the zip before you start. Two things catch
people out:

- **Use forward slashes in parameter files** (`C:/data/x.geno`). Backslashes
  work for most programs but silently break anything routed through the
  internal shell, notably gzipped input.
- **Keep the folder layout.** `qpGraph`, `qpAdm`, `qpWave`, `qpfstats` and
  `convertf` run helper commands via a shell, and `cygwin1.dll` locates that
  shell relative to its own directory. Moving a lone `.exe` elsewhere fails at
  runtime.

## Building from source

The build needs **Cygwin** specifically — not MSYS2 or mingw. `src/Makefile`
selects `-lblas -llapack` on Cygwin and `-lopenblas` elsewhere, and the 64-bit
transpose support assumes LP64, which mingw (LLP64) is not.

```sh
# from a Cygwin shell
cd src
make clobber
make all
make install        # executables land in ../bin
```

Required Cygwin packages: `gcc-core make binutils libgsl-devel
liblapack-devel libopenblas`.

> **Do not build for Linux and Windows in the same working tree.** `make`
> leaves its object files in `src/` with no per-platform separation, so the
> second build reuses the first one's `.o` files and the link fails with
> `undefined reference to fatalx`. Use separate checkouts, or remove
> `src/*.o src/nicksrc/*.o src/nicksrc/libnick.a` in between. Note that
> `make clobber` also wipes `../bin`.

To produce a redistributable bundle from a built tree:

```sh
sh src/test/make_bundle.sh src /tmp/bundle
```

It computes the DLL closure with `objdump` rather than hard-coding it, which
matters because Cygwin keeps `cyglapack-0.dll` in `/usr/lib/lapack` rather than
`/usr/bin`, and `cygcheck` silently omits DLLs it cannot find.

## Testing

`.github/workflows/regression.yml` guards the port against drifting from
upstream behaviour. Goldens in `src/test/goldens` were recorded from a build of
**pristine upstream on Linux**, the platform upstream targets. Both a Linux and
a Windows/Cygwin build of this branch are then compared against them, so a
mismatch means the port changed behaviour.

Covered on a seeded synthetic dataset (9 populations, 20 000 SNPs, real
admixture structure, generated by `src/test/gen_testdata.py`):

| check | how |
|---|---|
| `qpAdm` | full output compared field by field |
| `qpfstats` | run directly; `fstats.txt` and stdout both compared |
| `convertf`, `transpose`, `merge_transpose` | output files compared by SHA-256 |
| `transpose --low-mem` | must match the default path byte for byte |
| CRLF list files | must work (upstream strips only `\n` and fails) |
| shadowed `GENO_HEADER_SIZE` | must be defined exactly once |
| dangerous compiler warnings | build fails on them |
| standalone bundle | every executable must launch with Cygwin off `PATH` |

The dataset simulates known admixture weights, and `qpAdm` recovers them to
within about 0.02, so the goldens are checkable against a known answer rather
than being merely whatever the binaries printed.

## Versioning

Branches and releases are named `v<upstream version>-win-<n>`, where `n`
increments for each batch of upstream commits built for Windows and resets when
the upstream version changes. Release tags drop the `win` segment
(`v8.1.0-1`), because git will not allow a tag and a branch to share a name.
